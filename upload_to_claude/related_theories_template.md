## 2.1 แชทบอทและวิวัฒนาการสู่ LLM-based Agent

### (A) ตัวอย่างเนื้อหา

แชทบอท (Chatbot) คือโปรแกรมคอมพิวเตอร์ที่ออกแบบมาเพื่อจำลองการสนทนากับผู้ใช้ผ่านข้อความหรือเสียง มีวัตถุประสงค์เพื่อช่วยตอบคำถาม ให้ข้อมูล หรือปฏิบัติภารกิจที่กำหนดไว้ สามารถแบ่งออกเป็น 4 ประเภทตามวิวัฒนาการทางเทคโนโลยี ได้แก่

ประเภทแรก **แชทบอทแบบกฎ (Rule-based Chatbot)** ใช้การจับคู่คำสำคัญ (keyword matching) หรือกฎที่เขียนไว้ล่วงหน้า เช่น ELIZA (Weizenbaum, 1966) เหมาะกับคำถามที่รูปแบบชัดเจน แต่ไม่ยืดหยุ่น

ประเภทที่สอง **แชทบอทแบบเรียกคืนข้อมูล (Retrieval-based Chatbot)** ใช้การจำแนกเจตนา (Intent Classification) แล้วค้นคำตอบจากฐานข้อมูลที่เตรียมไว้ เช่น Dialogflow หรือ Rasa สามารถจัดการบทสนทนาได้ซับซ้อนขึ้น แต่ยังจำกัดอยู่ในชุดคำตอบที่กำหนด

ประเภทที่สาม **แชทบอทแบบสร้างคำตอบ (Generative Chatbot)** ใช้แบบจำลองภาษา (Language Model) สร้างคำตอบเอง เช่น ChatGPT สามารถตอบคำถามปลายเปิดได้ แต่ยังมีข้อจำกัดเรื่องการสร้างข้อมูลเท็จ (Hallucination) และไม่เข้าถึงข้อมูลเฉพาะโดเมน

ประเภทที่สี่ **แชทบอทแบบ LLM Agent** เป็นพัฒนาการล่าสุดที่ให้แบบจำลองภาษาขนาดใหญ่ทำหน้าที่เป็น "ผู้ตัดสินใจ" เลือกใช้เครื่องมือภายนอก (Tools) เพื่อดึงข้อมูลจริง แทนการสร้างคำตอบจากความรู้ภายในเพียงอย่างเดียว ทำให้แก้ปัญหาการสร้างข้อมูลเท็จและสามารถจัดการข้อมูลเฉพาะโดเมนได้อย่างแม่นยำ

งานวิจัยนี้พัฒนาแชทบอทประเภท LLM Agent โดยเน้นการตอบคำถามเกี่ยวกับหลักสูตรวิทยาการคอมพิวเตอร์ มหาวิทยาลัยธรรมศาสตร์ ซึ่งต้องการข้อมูลที่ถูกต้องแม่นยำจากฐานข้อมูลของมหาวิทยาลัยโดยตรง

### (B) คำแนะนำการหาข้อมูล

- **สำหรับประวัติแชทบอท:** ค้นคำว่า *"chatbot history"*, *"evolution of chatbots"* ใน Google Scholar
- **ELIZA paper ต้นฉบับ:** Weizenbaum, J. (1966). *ELIZA—a computer program for the study of natural language communication between man and machine.*
- **Survey paper ที่ดีมาก:** Adamopoulou, E., & Moussiades, L. (2020). *An Overview of Chatbot Technology.* — มีแบ่งประเภทครบ

## 2.2 แบบจำลองภาษาขนาดใหญ่ (Large Language Model — LLM)

### (A) ตัวอย่างเนื้อหา

แบบจำลองภาษาขนาดใหญ่ (Large Language Model — LLM) คือโครงข่ายประสาทเทียมเชิงลึก (Deep Neural Network) ที่ได้รับการฝึกด้วยข้อมูลข้อความจำนวนมหาศาลเพื่อเรียนรู้รูปแบบของภาษามนุษย์ สามารถทำงานด้านการประมวลผลภาษาธรรมชาติ (Natural Language Processing — NLP) ได้หลายอย่าง เช่น การสรุป การแปลภาษา และการตอบคำถาม

LLM สมัยใหม่ส่วนใหญ่ใช้สถาปัตยกรรม Transformer (Vaswani et al., 2017) ซึ่งใช้กลไก Self-Attention ในการเรียนรู้ความสัมพันธ์ระหว่างคำต่าง ๆ ในประโยค ทำให้สามารถเข้าใจบริบทได้ดีกว่าสถาปัตยกรรมก่อนหน้า เช่น Recurrent Neural Network (RNN)

แม้ LLM จะมีความสามารถสูง แต่ยังมีข้อจำกัดสำคัญ 3 ประการ ได้แก่ (1) **การสร้างข้อมูลเท็จ (Hallucination)** สร้างคำตอบที่ฟังดูสมเหตุสมผลแต่ไม่ถูกต้อง (2) **ขอบเขตความรู้ (Knowledge Cutoff)** ไม่มีข้อมูลหลังช่วงที่ฝึกโมเดล และ (3) **ขาดความรู้เฉพาะโดเมน** ไม่มีข้อมูลภายในองค์กรหรือเอกสารเฉพาะทาง

งานวิจัยนี้เลือกใช้ OpenThaiGPT ซึ่งเป็น LLM ภาษาไทยที่พัฒนาโดยสมาคมผู้ประกอบการปัญญาประดิษฐ์ประเทศไทย เนื่องจากให้ผลลัพธ์การประมวลผลภาษาไทยที่ดีกว่าโมเดลทั่วไป และสามารถเรียกใช้ผ่าน ThaiLLM Playground API ได้โดยสะดวก

### (B) คำแนะนำการหาข้อมูล

- **Paper ต้นฉบับ Transformer:** Vaswani et al. (2017). *Attention Is All You Need.* — อ้างอิงต้องมี
- **Survey LLM:** Zhao et al. (2023). *A Survey of Large Language Models.* — รวบรวมทุกเรื่องของ LLM
- **OpenThaiGPT:** เว็บ openthaigpt.aieat.or.th และ GitHub repo — อ้างเป็นแหล่งทางการ
- **Hallucination:** Ji et al. (2023). *Survey of Hallucination in Natural Language Generation.*

## 2.3 LLM Agent และการเรียกใช้เครื่องมือ (Tool Use)

### (A) ตัวอย่างเนื้อหา

LLM Agent คือระบบที่ให้แบบจำลองภาษาขนาดใหญ่ทำหน้าที่เป็นศูนย์กลางในการตัดสินใจ (Reasoning Core) โดยมีความสามารถในการเรียกใช้เครื่องมือภายนอก (Tools) เพื่อปฏิบัติภารกิจ แทนการสร้างคำตอบจากความรู้ภายในเพียงอย่างเดียว แนวคิดนี้ทำให้ LLM ก้าวข้ามข้อจำกัดเรื่องการสร้างข้อมูลเท็จและขอบเขตความรู้ได้อย่างมีประสิทธิภาพ

กรอบแนวคิดที่ได้รับการอ้างอิงมากที่สุดคือ **ReAct (Reasoning + Acting)** ของ Yao et al. (2023) ซึ่งเสนอว่า LLM ควรสลับระหว่างการใช้เหตุผล (Reasoning) และการปฏิบัติการ (Acting) โดยวางโครงการตัดสินใจเป็นวงรอบ Thought → Action → Observation → Thought จนกว่าจะได้คำตอบสุดท้าย

การเรียกใช้เครื่องมือ (Tool Use หรือ Function Calling) เป็นกลไกที่ทำให้ LLM Agent สามารถโต้ตอบกับระบบภายนอกได้ เช่น เรียกฟังก์ชันค้นฐานข้อมูล เรียก API ภายนอก หรือดึงข้อมูลจากเอกสาร งานวิจัยนี้ใช้แนวทาง Tool Use เพื่อให้ LLM เลือกใช้ฟังก์ชันค้นข้อมูลหลักสูตร 5 ฟังก์ชัน ได้แก่ การนับจำนวนวิชา การดึงรายละเอียดวิชา การตรวจสอบวิชาบังคับก่อน การค้นเส้นทางการเรียน และการแสดงแผนการเรียน

### (B) คำแนะนำการหาข้อมูล

- **Paper ReAct (สำคัญมาก):** Yao, S., et al. (2023). *ReAct: Synergizing Reasoning and Acting in Language Models.* ICLR 2023
- **Toolformer:** Schick et al. (2023). *Toolformer: Language Models Can Teach Themselves to Use Tools.*
- **Survey LLM Agent:** Xi et al. (2023). *The Rise and Potential of Large Language Model Based Agents: A Survey.*
- **Function Calling:** OpenAI documentation, Anthropic tool use documentation

## 2.4 การดึงข้อมูลเสริมการสร้างคำตอบ (Retrieval-Augmented Generation — RAG)

### (A) ตัวอย่างเนื้อหา

Retrieval-Augmented Generation (RAG) เป็นแนวทางที่เสนอโดย Lewis et al. (2020) เพื่อแก้ปัญหาข้อจำกัดของ LLM ในด้านการสร้างข้อมูลเท็จและการเข้าถึงข้อมูลเฉพาะโดเมน หลักการของ RAG คือการให้ LLM ดึงข้อมูลที่เกี่ยวข้องจากคลังเอกสารภายนอกก่อน แล้วนำข้อมูลนั้นมาประกอบการสร้างคำตอบ

ขั้นตอนการทำงานของ RAG ประกอบด้วย 4 ขั้นตอนหลัก ได้แก่ (1) **การแบ่งย่อยเอกสาร (Chunking)** แบ่งเอกสารออกเป็นส่วนย่อยขนาดเหมาะสม (2) **การแปลงเป็นเวกเตอร์ (Embedding)** ใช้โมเดลฝังแปลงข้อความเป็นเวกเตอร์ (3) **การค้นคืนข้อมูล (Retrieval)** ค้นส่วนเอกสารที่มีความหมายใกล้เคียงคำถาม และ (4) **การสร้างคำตอบ (Generation)** ส่งคำถามพร้อมบริบทที่ค้นได้ให้ LLM สร้างคำตอบ

งานวิจัยนี้ใช้แนวทาง **Hybrid Retrieval** ซึ่งผสมผสานการค้นข้อมูลจากสองแหล่ง ได้แก่ การค้นข้อมูลเชิงโครงสร้าง (Structured Retrieval) จากฐานข้อมูล SQLite เพื่อรับข้อมูลเชิงข้อเท็จจริงที่แม่นยำ เช่น รหัสวิชาและหน่วยกิต และการค้นข้อมูลเชิงความหมาย (Semantic Retrieval) จากฐานข้อมูลเวกเตอร์ Qdrant เพื่อรับบริบทเชิงพรรณนา เช่น คำอธิบายรายวิชา การผสมผสานทั้งสองแหล่งทำให้คำตอบมีทั้งความถูกต้องและความเป็นธรรมชาติ

### (B) คำแนะนำการหาข้อมูล

- **Paper RAG ต้นฉบับ (ต้องอ้าง):** Lewis, P., et al. (2020). *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks.* NeurIPS 2020
- **Survey RAG:** Gao et al. (2023). *Retrieval-Augmented Generation for Large Language Models: A Survey.*

## 2.5 การฝังเวกเตอร์และการค้นหาเชิงความหมาย (Embedding & Semantic Search)

### (A) ตัวอย่างเนื้อหา

การฝังเวกเตอร์ (Embedding) คือการแปลงข้อความให้เป็นเวกเตอร์ตัวเลขในปริภูมิหลายมิติ โดยที่ข้อความที่มีความหมายใกล้เคียงกันจะมีเวกเตอร์อยู่ในบริเวณใกล้กันในปริภูมิ หลักการนี้ช่วยให้คอมพิวเตอร์สามารถเปรียบเทียบความเหมือนของข้อความในเชิงความหมาย ไม่ใช่เพียงการจับคู่คำตรงตัว

โมเดลฝังสมัยใหม่มักพัฒนาบนพื้นฐานของ Transformer เช่น Sentence-BERT (Reimers & Gurevych, 2019) ซึ่งปรับปรุง BERT ให้สามารถสร้างเวกเตอร์แทนประโยคได้อย่างมีประสิทธิภาพ งานวิจัยนี้ใช้โมเดลจากไลบรารี sentence-transformers เพื่อแปลงทั้งคำถามของผู้ใช้และคำอธิบายรายวิชาให้เป็นเวกเตอร์

การวัดความเหมือนของเวกเตอร์นิยมใช้ **Cosine Similarity** ซึ่งวัดมุมระหว่างเวกเตอร์สองตัว ค่ายิ่งใกล้ 1 ยิ่งมีความหมายใกล้เคียงกัน สำหรับการค้นหาในคลังเวกเตอร์ขนาดใหญ่ การเปรียบเทียบทุกคู่จะใช้เวลามาก จึงนิยมใช้อัลกอริทึมค้นหาเพื่อนบ้านใกล้ที่สุดเชิงประมาณ (Approximate Nearest Neighbor — ANN) เช่น Hierarchical Navigable Small World (HNSW) ซึ่งเป็นอัลกอริทึมที่ Qdrant เลือกใช้

- **Word2Vec (ปูพื้น):** Mikolov et al. (2013). *Efficient Estimation of Word Representations in Vector Space.*
- **HNSW algorithm:** Malkov & Yashunin (2018). *Efficient and robust approximate nearest neighbor search using Hierarchical Navigable Small World graphs.*

## 2.6 ฐานข้อมูลเวกเตอร์และฐานข้อมูลเชิงสัมพันธ์ (Vector DB & Relational DB)

### (A) ตัวอย่างเนื้อหา

ฐานข้อมูลเวกเตอร์ (Vector Database) คือระบบจัดเก็บและค้นคืนข้อมูลที่ออกแบบมาเฉพาะสำหรับการทำงานกับเวกเตอร์หลายมิติ รองรับการค้นหาแบบเพื่อนบ้านใกล้ที่สุดเชิงประมาณ (ANN) ได้อย่างมีประสิทธิภาพ ต่างจากฐานข้อมูลเชิงสัมพันธ์ที่เน้นการค้นด้วยคำค้นตรงตัว งานวิจัยนี้ใช้ **Qdrant** ซึ่งเป็นฐานข้อมูลเวกเตอร์แบบ open-source รองรับการค้นด้วยอัลกอริทึม HNSW และสามารถติดตั้งในสภาพแวดล้อมท้องถิ่นได้สะดวก

ในทางกลับกัน ข้อมูลที่มีโครงสร้างชัดเจน เช่น รหัสวิชา ชื่อวิชา หน่วยกิต และความสัมพันธ์ระหว่างวิชาบังคับก่อน จำเป็นต้องเก็บในฐานข้อมูลเชิงสัมพันธ์เพื่อให้สามารถค้นด้วยคำสั่ง SQL ได้อย่างแม่นยำ งานวิจัยนี้เลือกใช้ **SQLite** เพราะเป็นระบบจัดการฐานข้อมูลขนาดเล็ก ไม่ต้องติดตั้ง server แยก และเหมาะกับข้อมูลขนาดที่งานวิจัยต้องการ

การใช้ฐานข้อมูลสองประเภทร่วมกัน (Hybrid Database) ช่วยให้ระบบได้ประโยชน์จากจุดแข็งของทั้งสองแบบ คือ ความแม่นยำของข้อมูลเชิงโครงสร้างจาก SQLite และความยืดหยุ่นของการค้นเชิงความหมายจาก Qdrant

## 2.7 การประเมินผลระบบ RAG (RAG Evaluation)

### (A) ตัวอย่างเนื้อหา

การประเมินผลระบบ RAG มีความซับซ้อนกว่าการประเมินระบบ NLP ทั่วไป เนื่องจากต้องประเมินทั้งคุณภาพของข้อมูลที่ค้นคืนได้ (Retrieval Quality) และคุณภาพของคำตอบที่สร้างขึ้น (Generation Quality) **Ragas** (Es et al., 2023) เป็นกรอบการประเมินที่ได้รับความนิยม โดยเสนอเมตริกหลัก 4 ตัว ได้แก่

**(1) Faithfulness** วัดว่าคำตอบที่สร้างขึ้นมีความสอดคล้องกับบริบทที่ดึงมาหรือไม่ ใช้ตรวจจับการสร้างข้อมูลเท็จ **(2) Answer Relevancy** วัดว่าคำตอบตรงกับคำถามของผู้ใช้มากน้อยเพียงใด **(3) Context Precision** วัดว่าบริบทที่ค้นคืนมามีความเกี่ยวข้องกับคำถามหรือไม่ **(4) Context Recall** วัดว่าบริบทที่ค้นคืนครอบคลุมข้อมูลที่จำเป็นต่อการตอบคำถามครบถ้วนหรือไม่

Ragas ใช้แนวคิด **LLM-as-a-Judge** ซึ่งให้แบบจำลองภาษาขนาดใหญ่อีกตัวทำหน้าที่เป็นผู้ประเมิน แทนการใช้ข้อมูลเฉลยที่มนุษย์สร้าง วิธีนี้ช่วยให้ประเมินได้เร็วและประหยัดแรงงาน แต่ก็มีข้อควรระวังเรื่องความเอนเอียง (Bias) ของโมเดลผู้ประเมิน งานวิจัยนี้จึงเลือกใช้ **Google Gemini** เป็นโมเดลผู้ประเมิน เพื่อให้แยกจาก OpenThaiGPT ที่ใช้สร้างคำตอบ ลดความเสี่ยงของการลำเอียง (self-evaluation bias)

### (B) คำแนะนำการหาข้อมูล

- **Paper Ragas (ต้องอ้าง):** Es, S., et al. (2023). *RAGAS: Automated Evaluation of Retrieval Augmented Generation.*
- **Ragas docs:** docs.ragas.io — อ่านทุกเมตริกให้เข้าใจ
- **LLM-as-a-Judge:** Zheng et al. (2023). *Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena.*
- **Evaluation survey:** Chang et al. (2023). *A Survey on Evaluation of Large Language Models.*
- **คำค้น:** *"RAG evaluation"*, *"Ragas metrics"*, *"LLM as judge"*, *"faithfulness NLG"*

## 2.8 งานวิจัยที่เกี่ยวข้อง (Related Work)

### (A) ตัวอย่างเนื้อหา

งานวิจัยด้านแชทบอทให้คำปรึกษาการศึกษา (Academic Advising Chatbot) ได้รับความสนใจอย่างกว้างขวางทั้งในประเทศและต่างประเทศ โดยสามารถแบ่งตามเทคโนโลยีที่ใช้ได้เป็น 3 กลุ่มดังนี้

**กลุ่มแรก แชทบอทแบบ Intent Classification** เช่น งานของ [ชื่อรุ่นพี่/ผู้เขียน] (ปี) ที่พัฒนาแชทบอทให้คำปรึกษาการลงทะเบียนด้วย Dialogflow ซึ่งสามารถตอบคำถามที่เตรียมไว้ล่วงหน้าได้ดี แต่ขาดความยืดหยุ่นในการตอบคำถามปลายเปิด

**กลุ่มที่สอง แชทบอทแบบ RAG ล้วน** เช่น งานของ [ชื่อผู้เขียน] ที่ใช้ LLM ร่วมกับฐานข้อมูลเวกเตอร์ในการตอบคำถามเกี่ยวกับหลักสูตร สามารถตอบคำถามปลายเปิดได้ดีกว่ากลุ่มแรก แต่ยังมีปัญหาเรื่องความแม่นยำของข้อมูลเชิงโครงสร้าง เช่น จำนวนหน่วยกิตและรหัสวิชา

**กลุ่มที่สาม แชทบอทแบบ LLM Agent** ซึ่งเป็นแนวทางที่งานวิจัยนี้ใช้ ยังมีงานวิจัยในบริบทภาษาไทยจำกัด โดยเฉพาะการประยุกต์ใช้กับข้อมูลหลักสูตรมหาวิทยาลัยไทย

งานวิจัยนี้จึงเติมเต็มช่องว่างดังกล่าวด้วยการผสมผสาน LLM Agent เข้ากับ Hybrid Retrieval (SQLite + Qdrant) เพื่อให้ได้ทั้งความแม่นยำของข้อมูลเชิงข้อเท็จจริง และความยืดหยุ่นในการตอบคำถามปลายเปิด ซึ่งเป็นจุดเด่นที่แตกต่างจากงานวิจัยก่อนหน้า

### (B) คำแนะนำการหาข้อมูล

- **งานไทย:** ค้น **TU Digital Collections** (digital.library.tu.ac.th), **Chula Thesis**, **TDC (ThaiLIS)** ด้วยคำค้น *"แชทบอท หลักสูตร"*, *"chatbot academic advisor"*
- **งานต่างประเทศ:** Google Scholar ด้วย *"academic advising chatbot"*, *"course advisor AI"*, *"university chatbot LLM"*
- **งานแนว LLM Agent สำหรับการศึกษา:** ค้น *"educational LLM agent"*, *"tutoring agent LLM"*

  - เขียนเรียงจากไกล → ใกล้ (general → specific)

## 2.9 กรอบมาตรฐานคุณวุฒิระดับอุดมศึกษา (TQF / มคอ.2) *(หัวข้อเสริม)*

### (A) ตัวอย่างเนื้อหา

กรอบมาตรฐานคุณวุฒิระดับอุดมศึกษาแห่งชาติ (Thai Qualifications Framework — TQF) เป็นกรอบมาตรฐานของสำนักงานปลัดกระทรวงการอุดมศึกษาฯ ที่กำหนดให้สถาบันอุดมศึกษาจัดทำเอกสารรายละเอียดของหลักสูตรตามแบบฟอร์ม มคอ.2 ซึ่งประกอบด้วยข้อมูลสำคัญ เช่น โครงสร้างหลักสูตร รายวิชา คำอธิบายรายวิชา วิชาบังคับก่อน และแผนการเรียนแต่ละชั้นปี

งานวิจัยนี้ใช้เอกสาร มคอ.2 ของหลักสูตรวิทยาศาสตรบัณฑิต สาขาวิชาวิทยาการคอมพิวเตอร์ (หลักสูตรปรับปรุง พ.ศ. 2566) มหาวิทยาลัยธรรมศาสตร์ เป็นแหล่งข้อมูลหลักในการสร้างฐานข้อมูลของระบบ เนื่องจากเป็นเอกสารทางการที่ครอบคลุมข้อมูลหลักสูตรครบถ้วน

### (B) คำแนะนำการหาข้อมูล

- **เอกสาร มคอ.2 ของคณะ:** ดาวน์โหลดจากเว็บคณะวิทยาศาสตร์ฯ หรือขอจากอาจารย์ที่ปรึกษา
- **กรอบ TQF:** สำนักมาตรฐานและประเมินผลอุดมศึกษา — ค้น *"TQF2 มคอ.2"*
- **ใส่เป็น citation:** (มหาวิทยาลัยธรรมศาสตร์, 2566)
